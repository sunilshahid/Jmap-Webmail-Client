# Secure Messaging API Guide

The Secure Messaging API allows external applications to generate secure, encrypted, zero-knowledge messages. The API relies on client-side encryption (AES-GCM), meaning the server never sees the plaintext data and requires zero knowledge of your encryption password.

## 1. Authentication
All requests must be authenticated via a Bearer token.
You can generate API keys from the **API** settings page in the application UI.

```http
Authorization: Bearer sk_your_api_key_here
```

## 2. Generate a Secure Message

**Endpoint:** `POST /api/v1/secure-message`

### Request Body Schema
The request body must be a JSON object containing the encrypted payload and its metadata.

```json
{
  "encryptedPayload": "base64_encoded_string_of_the_encrypted_data",
  "iv": "base64_encoded_initialization_vector",
  "salt": "base64_encoded_cryptographic_salt",
  "expiration": "1week",
  "viewOnce": false
}
```

### Encryption Requirements (Client-Side)
Before sending the payload to the server, you must encrypt the data using **AES-GCM**.
The plaintext data **MUST** be a valid JSON object containing at least a `subject`, `body`, and optionally an `attachments` array:

```json
{
  "subject": "Confidential Report",
  "body": "This is the secure content of the message.",
  "attachments": [
    {
      "name": "diagram.png",
      "type": "image/png",
      "size": 1048576,
      "data": "data:image/png;base64,iVBORw0KGgoAAAAN..."
    },
    {
      "name": "video.mp4",
      "type": "video/mp4",
      "size": 2097152,
      "data": "data:video/mp4;base64,AAAAIGZ0eXBpc29t..."
    }
  ]
}
```
*Note on attachments:* The Secure Message portal supports all file types (images, videos, PDFs, zip, etc.). They will be rendered if supported by the browser (such as images), or presented as secure downloads securely processed in-memory directly on the client. The `data` property can be raw Base64 or a full Base64 Data URI.

### Expiration Time (`expiration`)
The expiration field controls how long the server retains the encrypted payload before forcefully purging it from memory. You can use predefined shortcuts or custom timestamps.

**Predefined Options:**
- `"5min"` - Expires after 5 minutes
- `"1hour"` - Expires after 1 hour
- `"1day"` - Expires after 1 day
- `"1week"` - Expires after 1 week
- `"burn"` - Automatically sets maximum TTL (30 days) and forces `viewOnce: true`

**Custom Date/Time:**
You can provide an exact custom expiration date using an ISO 8601 string or a Unix Timestamp.
*Example (ISO String):* `"2025-12-31T23:59:59.000Z"`
*Example (Date String):* `"Wed, 21 Oct 2026 07:28:00 GMT"`
*How it works*: The server calculates the difference between the provided time and the current time and sets the TTL accordingly. If the date is in the past, it defaults to the standard 24 hours.

### View Once / Burn After Reading (`viewOnce`)
- `false`: The message can be viewed multiple times before the expiration time is reached.
- `true`: The first time the message is successfully fetched from the server, it is instantly and permanently deleted from memory.

## 3. Response Structure
On success, the server responds with the secure URL.

```json
{
  "id": "e2cd77b3-1250-4d47-9759-abcd1234efgh",
  "url": "https://your-domain.com/secure/e2cd77b3-1250-4d47-9759-abcd1234efgh",
  "expiresAt": 1716383637152,
  "viewOnce": false
}
```

## 4. Zero-Knowledge "Passwordless" URLs
Because the server does not know your decryption password, it only generates the base URL `/secure/:id`.
To create an auto-decrypting URL for your recipients (where they don't have to manually type the password), append your password as a URL fragment (`#password`) to the URL generated by the API:

```text
https://your-domain.com/secure/e2cd77b3-1250-4d47-9759-abcd1234efgh#my_secret_password
```

When the user opens this link, the React application automatically extracts the password from the URL hash, decrypts the message locally in the browser, and renders the content.

## 5. Node.js Example Script
You can use the following Node.js code to encrypt your payload and interact with the API:

```javascript
import crypto from 'crypto';

async function generateSecurePayload(password, subject, body) {
  const salt = crypto.randomBytes(16);
  const iv = crypto.randomBytes(12);

  const keyMaterial = await crypto.subtle.importKey(
    "raw", new TextEncoder().encode(password), { name: "PBKDF2" }, false, ["deriveKey"]
  );
  
  const key = await crypto.subtle.deriveKey(
    { name: "PBKDF2", salt, iterations: 100000, hash: "SHA-256" },
    keyMaterial, { name: "AES-GCM", length: 256 }, false, ["encrypt"]
  );

  const payloadStr = JSON.stringify({ subject, body, attachments: [] });
  const encrypted = await crypto.subtle.encrypt(
    { name: "AES-GCM", iv }, key, new TextEncoder().encode(payloadStr)
  );

  const requestBody = {
    encryptedPayload: Buffer.from(encrypted).toString('base64'),
    iv: Buffer.from(iv).toString('base64'),
    salt: Buffer.from(salt).toString('base64'),
    expiration: "2026-12-31T23:59:59.000Z", // Custom ISO time, or use "1week" 
    viewOnce: false
  };

  const response = await fetch('http://localhost:3000/api/v1/secure-message', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer sk_your_api_key'
    },
    body: JSON.stringify(requestBody)
  });

  const data = await response.json();
  console.log("Secure URL:", data.url + '#' + password);
}

generateSecurePayload("my_secret", "Demo", "Hello world!");
```
